# Email Integration

## Application email

The platform has no custom domain, so it sends through Gmail SMTP as `ndcakofficial@gmail.com` using a Google App Password. Delivery lives in `src/lib/email/send.ts`. A shared React Email layout follows the navy, gold, ivory, and green NDCAK design system and renders both HTML and plain text.

Gmail allows roughly 500 messages a day from a personal account, which covers registration receipts, decisions and staff invitations for this event. If NDCAK later buys a domain, a domain-based provider can replace the transport in that one file.

Implemented states:

| State                                  | Delivery                                                 |
| -------------------------------------- | -------------------------------------------------------- |
| Registration received / pending review | Wired to the registration outbox                         |
| Registration confirmed                 | Wired to approval; includes a calendar invitation        |
| Registration rejected                  | Wired to rejection; includes the participant-safe reason |
| Operator invitation                    | Wired to the staff invitation outbox and retry flow      |
| Event reminder                         | Template ready; job scheduling belongs to Phase 5        |
| Schedule change                        | Template ready; event-change dispatch belongs to Phase 5 |
| Support acknowledgment                 | Template ready; support intake is not built yet          |

Preview every state locally at `/dev/email-preview`. The preview contains fictional details, never sends email, and returns 404 outside development. Do not use its dates or links as event configuration.

Run `pnpm test:e2e` after installing Playwright Chromium to check all seven states at desktop and mobile widths. The checks cover full email height, visible support footer, and horizontal overflow; the preview does not send messages.

Environment contract:

- `SMTP_USER` - the Gmail address that sends mail.
- `SMTP_PASSWORD` - a Google App Password for that account; never client-exposed or committed. Spaces are ignored.
- `EMAIL_FROM_NAME` - display name, default `NDCAK Indoor Games`.
- `EMAIL_REPLY_TO` - organizer inbox for participant replies.
- `SMTP_HOST` / `SMTP_PORT` - optional; default `smtp.gmail.com` and `465`.

Create the App Password: sign in to the Gmail account, turn on 2-Step Verification under Google Account → Security, then open Security → App passwords, create one named "NDCAK platform", and paste the 16-character code into `SMTP_PASSWORD` in `.env.local` and in Vercel. Run `pnpm readiness:check`; it logs in to Gmail without sending anything.

Before production email, send and inspect one registration acknowledgment and one staff invitation to a different inbox.

## Supabase Auth SMTP

Staff invitations and setup links are generated by the application and sent through the app's own email transport, so they do not depend on Supabase's mailer. Supabase only sends its own emails for flows the app does not use today (such as Supabase-hosted password reset). If one is added later, configure the same Gmail account under Supabase Dashboard → Authentication → SMTP Settings: host `smtp.gmail.com`, port `465`, username the Gmail address, password the App Password, sender name `NDCAK Indoor Games`.

## Delivery rules

- Notification outbox rows are committed with the authoritative database change; sending starts only after commit.
- Email failures are recorded and retried; they do not roll back registration or review transactions.
- Each message is claimed in the outbox before sending, so it is attempted once per claim; the database status is the authoritative retry gate.
- Provider errors and credentials are never returned to the browser.
- Submission email always says pending review and never includes a calendar file.
- Approval email requires configured event start/end times and includes an RFC 5545 `.ics` invitation.
- Rejection email includes only the participant-safe reason entered by the administrator.
- Failed and queued messages can be retried from `/admin/notifications` without repeating the registration decision.
- Operator invitations are created only by a Super Admin. A Supabase invite link is generated immediately before email delivery; retry generates a fresh time-limited link. The link opens `/staff/set-password` after verification.
- App emails contain no payment transaction ID, receiving account, or internal review note.
